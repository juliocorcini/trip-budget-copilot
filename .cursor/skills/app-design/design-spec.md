# Design System Document Specification

> Spec for the `design-system.md` file generated by the /design skill.
> This document is the "visual constitution" — any AI reading it must be able to
> create new screens matching the exact visual identity without seeing the wireframes.

---

## Purpose

Single source of visual truth for the app. Contains ALL approved design tokens,
component patterns, layout rules, and anti-patterns. The developer's AI reads this
and implements every UI element following these rules.

- `v1-screen-list.md` (shared components list)

### Inputs
- Background: --surface-container
- Border: 1px --surface-container-high at 20% opacity (ghost border)
- Focus: border becomes --primary at 100% + outer glow --primary at 30%
- Border radius: [value]
- Label above input, helper text below, error text below in --error

### Cards
- Background: --surface-container
- Border radius: [value]
- No explicit border (use background shift for depth)
- Elevation via tonal layering (lighter bg = higher elevation), NOT drop shadows
- NEVER nest cards inside cards

### Tables / Data
- Header row: --surface-container-high background
- Row hover: --surface-container
- Borders: none (use spacing or subtle background shift between rows)
- Use tabular-nums for numeric columns
- Pagination below table

### Modals
- Overlay: --surface at 80% opacity + backdrop-blur-xl
- Modal card: --surface-container, centered
- Transform origin: center (exception to popover rule)
- Enter: scale(0.95) + opacity(0) → scale(1) + opacity(1), 250ms ease-out
- Exit: 150ms, faster than enter

### Toast Notifications
- Position: bottom-right (or bottom-center on mobile)
- Style: --surface-container-high with slight glassmorphism
- Enter from bottom with translateY
- Stack with spacing, max 3 visible
- Auto-dismiss after 5s, manual dismiss on swipe

### Empty States
- Centered in content area
- Illustration or icon (Material Symbols, 48px, --on-surface-dim)
- Heading: what's empty
- Description: how to populate
- CTA button to create first item

### Badges / Status
- Small pills with rounded-full
- Color-coded: success/warning/error/info/neutral
- Background at 10% opacity of status color, text at full status color

## 7. Motion & Animation

### Easing Curves
```css
--ease-out: cubic-bezier(0.23, 1, 0.32, 1);
--ease-in-out: cubic-bezier(0.77, 0, 0.175, 1);
--ease-spring: cubic-bezier(0.34, 1.56, 0.64, 1);
```

### Duration Scale
| Element | Duration | Easing |
|---|---|---|
| Button feedback | 100-160ms | ease-out |
| Tooltip, popover | 125-200ms | ease-out |
| Dropdown, select | 150-250ms | ease-out |
| Modal, drawer | 200-350ms | ease-out |
| Page transition | 300-500ms | ease-in-out |

### Animation Rules (from Emil Kowalski)
- NEVER animate from scale(0) — start from scale(0.95) + opacity(0)
- NEVER use ease-in for UI — it feels sluggish
- NEVER animate width/height/padding/margin — only transform and opacity
- UI animations MUST stay under 300ms
- Buttons: add scale(0.97) on :active for tactile feedback
- Popovers: transform-origin from trigger (NOT center). Modals: keep center
- Stagger lists: 30-80ms between items
- Exit animations: faster than enter (enter 250ms, exit 150ms)
- Respect prefers-reduced-motion: keep opacity transitions, remove movement

## 8. Anti-Patterns (BANNED)

These patterns are BANNED. The AI must never produce them:

### From Impeccable
- Side-stripe borders (border-left > 1px with accent color)
- Gradient text (background-clip: text with gradient)
- Gray text on colored backgrounds
- Cards inside cards (flatten the hierarchy)
- Same-sized card grids repeated endlessly
- Hero metric layout (big number, small label, gradient accent)

### From Taste Skill
- Inter, Roboto, Arial as default fonts
- AI Purple/Blue aesthetic (purple button glows, neon gradients)
- Centered hero sections (when DESIGN_VARIANCE > 4)
- Emojis in UI
- Generic placeholder names ("John Doe", "Acme Corp")
- Round numbers in data ("99.99%", "$100.00")
- h-screen for full-height sections (use min-h-[100dvh])
- Unsplash links (use picsum.photos or SVG placeholders)

### From Emil Kowalski
- transition: all (specify exact properties)
- ease-in on UI elements
- Animation duration > 300ms on interactive elements
- No :active state on buttons
- Keyframes on rapidly-triggered elements (use CSS transitions)

### General
- Pure black (#000000) for any text or background
- Pure white (#ffffff) for backgrounds
- Default box-shadow (0 2px 4px) — use tonal layering
- 1px solid borders for section separation — use background shifts
- Loading spinners — use skeleton shimmer matching layout
